# v0.7.1 signing and recovery

Android package `io.github.styayur.calligraphystudio` uses versionName `0.7.1`, versionCode `8`, and a persistent release signing identity. The release workflow **requires** all four GitHub Actions secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`) and pins the public certificate SHA-256 through repository variable `ANDROID_CERT_SHA256`. Missing or partial production signing fails before building; the verifier checks the actual APK signature, certificate fingerprint, package ID and version. A debug-signed APK cannot enter the production release.

The release owner can provision or re-use the identity with `python scripts/provision_android_signing.py` on Windows with Java 21 `keytool` and authenticated `gh`. The script generates strong independent random store/key passwords only when no private identity exists, copies the keystore and recovery credentials into restricted local directories outside the repository, configures the GitHub secrets via standard input, and records the public certificate fingerprint. It never prints passwords. The primary files live in `%LOCALAPPDATA%\CalligraphyStudio\release-signing`; a local backup lives in `%USERPROFILE%\Documents\CalligraphyStudio-Private-Backup\android`. **Make an additional encrypted offline backup of both files now**: the two local copies may be on the same disk, and loss of the key or passwords can prevent users from installing future updates. Never commit, share or upload the recovery file publicly. On a replacement release machine, restore both private files with owner-only access and rerun the provisioning script to restore GitHub secrets. Preserve the signing certificate across all future Android releases.

The v0.7.0 Android build was a debug-signed preview and was not published. A debug-signed older install cannot upgrade in place to this release-signed APK; export projects before uninstalling any such preview. Version code 8 is reserved for v0.7.1.

No publicly trusted Authenticode certificate was available for Windows. The Windows installer and portable executable are distributed unsigned, with their SHA-256 checksums and `NotSigned` receipt. A local self-signed certificate is not a trusted production signature; SmartScreen or organisational restrictions may appear.
